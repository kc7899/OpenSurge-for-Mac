# 稳定选线与设备接入设计

状态：已讨论的产品目标与待验证设计，尚未实现。不得据此声称当前版本已具备这些能力。
本页是独立研发分支的方案，不覆盖上游现有运行契约；实现对应功能时同步修改领域文档。

## 目标与最小架构

当前合规节点健康时不主动替换。常规检测、冷却到期、优先级变化和恢复发现不得触发
配置应用、网关重载、进程重启或全连接清理。节点不变不保证服务商的实际公网 IP 不变。

复用 Control Service、现有来源库、Mihomo API、配置合成及设备观测入口，不建立第二套网关管理器。
自动选线只设置一个调度入口和串行执行入口；设备接入独立管理。节点健康失败不得被提升
为内核故障；现有 Mihomo 进程恢复由原生命周期机制负责，并与选线互斥。

第一版不加入带宽测速、动态评分、自适应冷却、自动抢回高优先级节点或自动 DHCP 接管。

## 来源身份与排序

- 使用稳定 source ID；名称、URL、列表位置均不得作为身份。
- 用户保存的 ID 顺序优先；未设置时按名称自然排序，数字段按数值比较。
- 任意名称、重复名称、大小写差异、前导零与超长数字必须得到确定顺序；等价时以 ID 决胜。
- 不包含特定名称、前缀或固定订阅数量判断，不纠正用户命名。
- 已保存顺序不因重命名改变，新来源追加末尾；删除来源同时清理无效排序引用。
- 顺序仅在需要寻找候选时生效，健康线路不因列表调整迁移。

## 选择与故障确认

默认每 60 秒检查当前节点，每 600 秒读取额度。手动检查与可靠的连接故障信号可以提前
唤醒同一调度器，不另外启动切换任务。一次应用请求失败不能视为节点失效。

初检失败后短暂间隔复测并使用独立 HTTPS 目标，同时区分 DNS、本机上网、核心控制接口
与代理出口问题。具体超时与复测间隔经隔离验证确定；不能只依赖单个外部站点。
网络恢复、睡眠唤醒时使过期探测结果失效，不能把睡眠时间计作连续失败。

候选顺序：

1. 当前订阅仍有资格时，先在当前订阅寻找其他节点。
2. 按用户配置的地区顺序选择；本次默认美国、新加坡、日本，同地区优先低 HTTPS 延迟。
3. 当前订阅明确耗尽、过期或全部合格节点确认失败后，按来源顺序寻找其他来源。
4. 跳过冷却、耗尽和过期来源。额度未知本身不取消资格；通过实际连通与地区检查才能使用。

地区策略配置化，不把国家顺序写入调度分支。本次策略禁止香港；硬性禁止不可由兜底绕过。
候选使用实际出口校验，不能仅看节点名字；未知地区不投入使用。地区服务失败与连接失败
分别记录。出口地区识别和服务商动态出口存在客观限制，UI 不承诺绝对固定 IP。

切换先验证候选，再提交一次选择，读回实际结果后更新持久化状态。提交超时先查明状态，
不得盲目重试。旧探测结果须绑定配置/来源版本和节点指纹，不能覆盖新设置或手动选择。
恢复时先核对真实核心选择，再恢复调度；不先清空当前选择，不默认切回排序第一项。

## 额度与冷却

- 额度区分：已知可用、已知耗尽/过期、未知；记录数据时间与来源。
- 下载 403、超时、缺少额度字段不等于耗尽，保留最后有效节点快照。
- 默认故障冷却 300 秒，可设置；恢复候选资格需连续成功两次。
- 冷却限制重新使用故障候选，不阻止立即离开已确认故障的当前线路。
- 冷却结束不触发健康连接迁移。耗尽/过期须有效额度/有效期信息确认恢复。
- 全部不可用时拒绝代理出口、保留既有大陆直连；每 60 秒检查上网状态，候选按冷却节奏
  有界复测。未知上网状态不应给所有订阅同时记失败。
- 约束探测并发、总时长与缓存有效期。未完成扫描不能宣称全部节点失效。

## 运行配置和切换边界

目标是在同一受管运行配置中加载多个来源的候选节点，通过稳定的 select 组与节点选择
API 完成日常切换。统一保留分流、DNS、设备和 Tailscale 规则，不随节点来源改变。
每个来源使用独立命名空间，避免重名及引用冲突。

先验证本机固定版本的 provider 更新、selection 保存、更新失败及现有连接行为。
现有 source apply 是完整 reload 事务，自动选线不得调用它。已有 selector API 应优先复用。
不得使用会清除自动组固定选择的整组测速来实现无副作用检查。

来源内容变化与选线分开处理。相同内容不应用；变化先在隔离环境校验，保留最后有效版本。
正在使用的节点被删除、字段改变或指纹变化时，应按明确的迁移事务处理，不借刷新暗中切换。
无法安全热更新时显示待应用状态；首次启用新配置结构与其他必要结构变更允许独立受控应用。

候选可在隔离核心验证，但不能临时改动正式选择进行测速。不得占用正式端口、TUN、DNS、
pf 或 forwarding。不能以一个 HTTPS 检查宣称 UDP、QUIC 或特定应用功能全部正常。
普通切换不清空所有连接；禁止地区等硬策略变化时，单独定义并验证旧关联连接处理。

## 设备自动登记与默认授权

在已配置下游 LAN 范围内复用 DHCP、邻居和连接观测发现设备。登记记录首次/最近出现时间、
可用地址及名称、身份依据和授权来源。无法确认持久身份时保留临时观测记录，不凭一个 IP
永久合并不同设备；IPv6 临时地址、MAC 随机化和地址重用需专门验收。

- `新设备自动放行` 默认开启。登记不成为代理接入的等待条件。
- `自动允许 Tailscale 私网访问` 默认开启；依赖设备获得放行以及 Tailscale 已配置且实际可用。
- 关闭自动放行后仍可发现登记，新设备待批准；已有批准不批量撤销。
- 关闭 Tailscale 自动允许只停止新的自动授权；已有授权的撤销通过独立显式操作完成。
- 显式设备拒绝优先于默认放行，防止拒绝后被发现任务重新批准。
- 自动登记不触发网关重载；默认放行需采用范围明确的接入规则，而不是每发现设备就重写运行配置。
- 不开放控制台管理权限、不自动加入 Tailnet、不修改 Tailnet ACL，不扩大到上游或公网来源。
- 设备发现与默认放行不改变 DHCP、DNS、客户端网关或 IPv6 接入方式；自动获得网关/DNS
  属于原有 DHCP 部署功能，不能仅靠自动登记实现。

上游 Tailscale 的“全部设备”目前指有效登记设备，本次目标包含尚未登记的合格 LAN 来源。
必须显式扩展配置语义和 Helper 编译规则，不能只改 UI 文案或控制面状态。迁移保留已有
明确拒绝与批准，不把新默认值误当成对存量权限的批量重置。IPv6 支持范围单独展示，未验证
时不能把 IPv4 验收描述为所有协议已放行。

## 控制台

共享 Web/桌面业务：自动总开关、来源顺序、检测/额度/冷却间隔、地区顺序与禁止地区。
展示实际来源、节点、出口 IP/地区、最近检测、切换原因、额度信息时效和冷却剩余时间。
设置保存、运行生效和核心不可达分别展示。关闭自动功能保留当前线路，不自动切成 DIRECT。
“立即检查”遵循稳定优先；手动选择和显式重新择优必须与此区分。

设备页展示观测与持久身份、授权来源、Tailscale 实际生效或阻塞原因。
日志只记状态变化及必要故障，不每秒刷屏，不记录订阅凭据。

## 实施阶段与验证

1. 对照干净基线审查现有改动；逐项迁移兼容修复，保留原有行为的回归验证。
2. 实现纯决策逻辑和版本化状态，以模拟时钟/检测结果验证排序、冷却、额度、恢复和并发。
3. 隔离真实 Mihomo 验证多来源合成、选择、探测和 provider 更新，观察 PID、配置及连接。
4. 独立完成设备观测登记与接入授权，验证 Helper 规则及存量权限迁移。
5. 接入共享控制台，检查设置/实际状态一致性和 Web/桌面能力边界。
6. 完成构建、隔离验证与回滚材料后安排一次受控安装；最后执行真实下游设备验收。

必须覆盖：

| 场景 | 预期 |
| --- | --- |
| 当前健康、其他节点更快或高优先级来源恢复 | 不切换，不重载 |
| 单个检测站点失败或本机断网 | 不误判全部订阅失效 |
| 当前节点失败但同来源仍有合格节点 | 验证后单次选择 |
| 当前来源有额度但合格节点均失败 | 查找其他来源 |
| 来源耗尽或过期 | 跳过，不能仅靠冷却恢复 |
| 下载 403 或额度缺失 | 更新失败/未知，保留可用快照 |
| 任意名称、重名、重命名、增删来源 | 身份稳定、顺序确定、无名称特判 |
| 所有来源失败 | 代理拒绝、直连规则保留、无重启循环 |
| 手动和定时检查并发，设置中途更新 | 单一执行，过期结果不覆盖新状态 |
| 服务恢复、睡眠唤醒、选择 API 超时 | 先核对实际状态，避免重复切换 |
| 新设备到来，默认放行开启 | 无人工审批、无逐设备重载 |
| 默认放行关闭或设备显式拒绝 | 不被后台发现自动批准 |
| Tailscale 自动允许开/关 | 来源与目标范围正确，实际权限可核验 |
